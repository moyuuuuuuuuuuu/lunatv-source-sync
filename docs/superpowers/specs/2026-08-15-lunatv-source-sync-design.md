# LunaTV 影视源同步服务设计

## 目标

构建一个面向 `linux/amd64` 的单容器服务，用于导入、合并、维护和检测 LunaTV 影视源，并向 LunaTV 实例提供支持分类、Base58、访问令牌和受控 CORS 代理的订阅接口。

首版面向单管理员和私有部署，优先快速交付，不实现注册、多用户、角色权限、任意 URL 代理或复杂任务队列。

## 技术方案

- Node.js + TypeScript 单体应用
- Fastify 提供管理 API、订阅 API、受控代理和静态资源
- Vue 3 + Vite 提供管理后台
- SQLite 保存业务数据，数据库位于 `/app/data/app.db`
- 应用内调度器执行全局周期健康检查
- 单个 Docker 镜像，仅构建 `linux/amd64`

容器只需挂载 `/app/data`。管理员凭据来自环境变量；订阅令牌由系统首次启动时生成并持久化，可在后台重置。

## 系统组成

### 管理后台

管理后台包含：

- 登录页
- 仪表盘：源总数、普通源数、成人源数、正常/异常/未检测数量和下次检测时间
- 源列表：搜索，按分类、启用状态和检测状态筛选
- JSON 导入：解析、预览新增/覆盖/无效数量，确认后写入
- 单源新增、编辑、删除、启用、停用和立即检测
- 批量删除、启用、停用和立即检测
- 成人分类模式：自动、强制成人、强制普通
- 检测策略：正常检测或忽略检测并始终发布
- 全局设置：检测周期小时数、请求超时、连续失败隐藏阈值和输出 `cache_time`
- 订阅地址展示与复制

登录使用环境变量中的单管理员账号密码。登录成功后签发短期、HttpOnly、SameSite Cookie。后台不提供修改密码功能；修改环境变量并重启容器后生效。

### JSON 导入与合并

接受以下 LunaTV 配置结构：

```json
{
  "cache_time": 7200,
  "api_site": {
    "source-key": {
      "name": "示例资源",
      "api": "https://example.com/api.php/provide/vod",
      "detail": "https://example.com",
      "_comment": "可选备注",
      "adult": false
    }
  }
}
```

导入规则：

- `api_site` 的对象键作为唯一 `source_key`
- 同键源由后导入的数据覆盖先前业务字段
- 覆盖时保留既有检测历史
- `name` 和 `api` 必填，`detail`、`_comment`、`adult` 可选
- 无效项目不写入，并在预览中给出原因
- 上传文件仅用于解析，不保存原始副本
- 导入文件中的 `cache_time` 不覆盖后台全局配置

### 成人源分类

系统对 `source_key`、`name`、`api`、`detail` 和 `_comment` 进行不区分大小写的关键词检测。内置关键词覆盖成人标记、中文成人词、常见英文缩写和常见成人站点词；环境变量可以追加关键词。

分类优先级为：

1. 显式 `adult: true`：强制成人
2. 显式 `adult: false`：强制普通
3. 未提供 `adult`：自动关键词检测

后台编辑使用 `auto`、`adult`、`normal` 三态表达该规则。对外订阅不输出内部分类字段。

### 数据持久化

SQLite 至少保存：

- 源唯一键及 LunaTV 业务字段
- 启用状态、成人分类模式和自动分类结果
- 是否忽略健康检查
- 当前健康状态、连续失败次数、最后检测时间、响应耗时和失败摘要
- 有上限的检测历史
- 全局检测设置和下次执行时间

删除源时同时删除其检测历史。所有写操作使用事务；导入预览不修改数据库。

## 订阅接口

接口形式：

```text
GET /api/source?ac=list&source=normal&format=json&proxy=0&token=...
GET /api/source?ac=list&source=all&format=base58&proxy=1&token=...
```

参数规则：

- `ac`：兼容参数，缺省或 `list` 均可；其他值返回 HTTP 400
- `source`：`normal`、`adult`、`all`，默认 `normal`
- `format`：`json`、`base58`，默认 `json`
- `proxy`：`0` 或 `1`，默认 `0`
- `token`：始终必填且必须匹配系统生成的当前订阅令牌

订阅仅包含已启用且符合以下任一条件的源：

- 尚未检测
- 当前正常
- 连续失败次数尚未达到隐藏阈值
- 配置为忽略检测

输出保持 LunaTV 的 `cache_time` 和 `api_site` 结构，并删除所有内部管理字段。`format=base58` 对紧凑 JSON 的 UTF-8 字节使用 Bitcoin Base58 字母表编码，不添加校验和。

订阅响应支持 `GET` 和 `OPTIONS`，并返回允许跨域读取的 CORS 响应头。

## 受控 CORS 代理

当 `proxy=1` 时，订阅中的每个 `api` 被改写为当前服务的受控代理地址：

```text
GET /api/proxy/:sourceKey?token=...
```

LunaTV 后续追加的 `ac`、`wd`、`pg`、`ids` 等查询参数由代理转发给该源在数据库中保存的真实 API。代理响应透传上游状态码、响应体和安全响应头，并补充 CORS 头。

安全约束：

- 外部请求不能直接提交目标 URL
- 只代理数据库内存在且启用的源
- 代理使用同一系统订阅令牌校验
- 只允许 HTTP 和 HTTPS
- 拒绝回环、链路本地、私有网段及云元数据地址
- 每次重定向都重新验证目标，阻止重定向绕过
- 设置响应超时和响应体大小上限
- 不透传 Cookie、Authorization 等敏感请求头

## 健康检查与调度

全局检测周期由后台配置为正整数小时数。修改周期后重新计算下次执行时间。应用启动时恢复调度；同一时刻只允许一个全局检测批次运行。

每个源的检测步骤：

1. 在源 API 上正确合并 `ac=list` 查询参数
2. 在全局超时内发起请求，失败时最多重试两次
3. 要求 HTTP 2xx
4. 要求响应可解析为 JSON 或 XML，并符合苹果 CMS 列表响应的基本结构
5. 保存状态、耗时和简短失败原因

检测采用有限并发，避免短时间耗尽网络连接。连续失败达到默认阈值 3 后从订阅隐藏；后续检测恢复正常时自动重新发布。新导入且未检测的源先进入订阅。设置为忽略检测的源始终发布，但仍可手动执行检测。

后台支持单源和批量立即检测。自动与手动检测复用同一实现。

## 登录与安全

建议环境变量：

```dotenv
ADMIN_USERNAME=admin
ADMIN_PASSWORD=change-me
SESSION_SECRET=replace-with-random-secret
PORT=3000
ADULT_KEYWORDS_EXTRA=
```

管理员登录接口限制连续失败请求频率。所有管理写接口要求有效会话并进行 CSRF 防护。日志不记录密码、Cookie 或完整 token。

## 错误处理

- 参数无效：HTTP 400 和稳定错误代码
- 未登录或 token 错误：HTTP 401
- 源不存在或不可代理：HTTP 404
- 上传结构错误：HTTP 422，并返回条目级错误
- 上游超时：HTTP 504
- 上游连接或协议错误：HTTP 502
- 数据库冲突或内部错误：HTTP 500，客户端只返回安全摘要

单个源检测失败不终止整个检测批次。导入确认阶段如发生数据库错误，整个导入事务回滚。

## 测试与验收

首版只保留高价值自动化测试：

- 同键导入覆盖且保留检测历史
- 成人关键词分类及显式覆盖
- `normal`、`adult`、`all` 过滤
- 连续失败隐藏和恢复发布
- Base58 编码与参考实现兼容
- 代理只能访问已登记源且拒绝内部网络
- 核心 Docker 启动和接口冒烟测试

人工验收包括登录、上传两份样例、编辑和删除、修改检测周期、手动检测、复制四类订阅地址，并在 LunaTV 实例中验证 JSON、Base58 和代理订阅。

## Docker 与版本控制

提供 `Dockerfile`、`docker-compose.yml` 和 `.env.example`。运行数据统一写入 `/app/data`，容器无需额外 cron 服务。

Git 只跟踪源码、数据库迁移、必要测试、Docker 配置、示例配置和文档。至少忽略：

```gitignore
.env
data/
uploads/
logs/
node_modules/
dist/
coverage/
*.db
*.db-shm
*.db-wal
```

不提交上传原件、运行数据库、日志、构建产物、依赖目录和真实凭据。

## 明确不做

- 用户注册、多管理员或角色权限
- 任意 URL 开放代理
- Cloudflare Worker 部署
- 外部 Git 仓库自动拉取源
- 多架构镜像
- 自动删除失败源
- 按单个源设置独立检测周期
- 复杂告警和通知渠道
